PathyaTech Developer Hub

The comprehensive tech stack reference, system layouts, workflows, and developer guide for the PathyaTech healthcare platform.

Project Overview

PathyaTech is an advanced full-stack healthcare ecosystem designed to link Patients, Doctors, Clinic Receptionists, and Administrators. It supports digital clinics, diagnostic test management, Gemini AI clinical reports, certified nutrition diets, and automatic notifications.

Next.js App Client

Decoupled App Router client built with React Context for sessions and vanilla CSS components.

Django REST API

Multi-app Python backend exposing secure REST endpoints, structured via Simple JWT and django-filter.

Local Setup & Install

Configure the developer environments to launch the platform services on your local machine.

1. Backend Setup & Run Guide

A. Prerequisites

Python 3.10+, pip installer, and virtualenv manager.

B. Installation Steps

# Navigate to backend
cd backend

# Configure python venv
python -m venv venv
source venv/bin/activate # Linux/macOS
# On Windows use: venv\Scripts\activate

# Install packages
pip install -r requirements.txt

C. Environment Variables

Create a file named .env in the backend/ directory:

# =========================
# CORE / DJANGO SETTINGS
# =========================
DEBUG=True
SECRET_KEY=your-django-secret-key-here
FRONTEND_URL=http://localhost:3000
ALLOWED_HOSTS=localhost,127.0.0.1
CORS_ALLOWED_ORIGINS=http://localhost:3000,http://127.0.0.1:3000

# =========================
# DATABASE (SUPABASE POSTGRES)
# =========================
DB_NAME=postgres
DB_USER=your-db-user
DB_PASSWORD=your-db-password
DB_HOST=your-db-host
DB_PORT=6543

# =========================
# PAYMENTS (RAZORPAY)
# =========================
RAZORPAY_KEY_ID=your-razorpay-key-id
RAZORPAY_KEY_SECRET=your-razorpay-key-secret
RAZORPAY_WEBHOOK_SECRET=your-razorpay-webhook-secret

# =========================
# CLOUD STORAGE (CLOUDINARY)
# =========================
CLOUDINARY_NAME=your-cloudinary-name
CLOUDINARY_KEY=your-cloudinary-key
CLOUDINARY_SECRET=your-cloudinary-secret
CLOUDINARY_URL=your-cloudinary-url

# =========================
# COMMUNICATION (ZOOM)
# =========================
ZOOM_ACCOUNT_ID=your-zoom-account-id
ZOOM_CLIENT_ID=your-zoom-client-id
ZOOM_CLIENT_SECRET=your-zoom-client-secret
ZOOM_SECRET_TOKEN=your-zoom-secret-token

# =========================
# AI SERVICES (GEMINI)
# =========================
GEMINI_KEY=your-gemini-api-key

# =========================
# EMAIL CONFIGURATION (SMTP)
# =========================
DEFAULT_FROM_EMAIL=your-email@gmail.com
EMAIL_BACKEND=django.core.mail.backends.smtp.EmailBackend
EMAIL_HOST=smtp.gmail.com
EMAIL_PORT=587
EMAIL_USE_TLS=True
EMAIL_HOST_USER=your-email@gmail.com
EMAIL_HOST_PASSWORD=your-gmail-app-password

D. Database Migrations & Run

# Run migrations to initialize the Supabase database
python manage.py makemigrations
python manage.py migrate

# Create a superuser account to log into the Django Admin dashboard
python manage.py createsuperuser

# Launch the development server
python manage.py runserver

The backend API will be active at http://127.0.0.1:8000/. View documentation pages at:

  • Swagger UI: http://127.0.0.1:8000/api/docs/
  • ReDoc: http://127.0.0.1:8000/api/redoc/

2. Frontend Setup & Run Guide

A. Prerequisites

Node.js v18.0.0+ and npm package manager.

B. Installation Steps

# Navigate to frontend
cd frontend

# Install package modules
npm install

C. Environment Variables

Create a file named .env.local in the frontend/ directory:

# URL of the main Django backend
NEXT_PUBLIC_BACKEND_URL=http://localhost:9000

# URL of the Lab module backend (if separate, otherwise same as backend)
NEXT_PUBLIC_LAB_BACKEND_URL=http://localhost:8000

# URL of the TrackIntake integration service
NEXT_PUBLIC_TRACKINTAKE_BACKEND_URL=http://localhost:7000

# Razorpay Key ID for client-side checkout
NEXT_PUBLIC_RAZORPAY_KEY_ID=rzp_test_your_key_id

D. Launching the App

# Start the Next.js development server
npm run dev

Open the client in your browser: http://localhost:3000

Troubleshooting tip: If database connection failures occur, verify that your local IP address is whitelisted in whitelists under Supabase network security settings.

Production Launch Roadmap

The operational checklist and architectural setups for deploying PathyaTech platform components to live production environments.

1. SMS OTP & Messaging Gateway

Swap local mock logs for live gateway connections (e.g. Twilio, Msg91). Register verified transactional templates under regulatory portals (DLT in India) and swap credentials:

SMS_API_KEY=your-production-gateway-secret-key
SMS_SENDER_ID=PATHYA
2. Razorpay Live Gateways

Register production API keys and register HTTPS Webhook urls pointing to: https://api.pathyatech.com/api/payments/verify-payment/ to secure state callbacks.

RAZORPAY_KEY_ID=rzp_live_xxxxxxxxxxxxxx
RAZORPAY_KEY_SECRET=production-secret-hash-key
RAZORPAY_WEBHOOK_SECRET=webhook-secret-hash
3. Enterprise Zoom Meetings

Generate Server-to-Server OAuth apps in Zoom App marketplace and register details under backend settings:

ZOOM_ACCOUNT_ID=your-zoom-account-id
ZOOM_CLIENT_ID=your-zoom-client-id
ZOOM_CLIENT_SECRET=your-zoom-client-secret
4. Connection Pooling (pgBouncer)

Scale DB handles by deploying pgBouncer in front of the Supabase PostgreSQL cluster to support high concurrent API requests.

Asynchronous Worker Architecture (Celery + Redis)

Delegating heavy payloads out of standard HTTP threads prevents server choking. Celery background queues process:

  • Gemini AI Analysis: Heavy report parsing and clinical summary evaluations.
  • Reminders Cron (Celery Beat): Hourly checks sending SMS alerts for upcoming slots.
  • Media Generation: Compiling invoice and prescription PDFs on slot confirmation.
# backend/core/celery.py configuration
import os
from celery import Celery

os.environ.setdefault('DJANGO_SETTINGS_MODULE', 'core.settings')
app = Celery('pathyatech')
app.config_from_object('django.conf:settings', namespace='CELERY')
app.autodiscover_tasks()

Detailed Component Integrations

Google Gemini AI Engine

Implements three clinical endpoints:

  • Diagnosis Assist: Analyzes health vital metrics to output potential diagnosis cards.
  • Report Interpreter: Translates clinical biomarker parameters into plain-text summaries.
  • Custom Query Box: Doctor-specific consultation assistant scanning past patient files.
Razorpay Security Gateway

Order IDs are created server-side based on database slot pricing. Checkout signatures are cryptographically validated using HMAC SHA256 before confirming bookings.

Third-Party Integrations

PathyaTech integrates with several third-party APIs to provide rich features:

Integration Technology/API Usage & Purpose
Payments Razorpay API Consultation slots and diagnostic cart checkouts. Uses HMAC SHA256 verification.
AI Operations Google Gemini API Calculates diet recommendations, translates lab reports, and answers clinical queries.
Telehealth Zoom Video API Generates online room links automatically for confirmed slots.
Comms Twilio / WhatsApp / SMTP Dispatches OTPs, booking receipts, and reminders.

Backend Core Architecture

The backend logic is split across modular Django apps, integrating Supabase PostgreSQL models and REST serializers.

Apps Directory Layout
backend/apps/
├── auth_app/      # Custom User model, Organization, OTPs
├── patients/      # Vitals, lifestyles profiles, locked slots
├── doctors/       # Profile, availability, education, bank accounts
├── appointments/  # Availability Slots, Booking Appointments
├── prescriptions/ # Diagnostic recommendation, medicine lines
├── payments/      # Payment logs, refund audits, ledger
├── documents/     # Vault storage with verification audit
└── communication/ # Twilio, WhatsApp integration codes
Relational Constraints & Database Schema
  • Custom User: Custom email-login. Roles: PATIENT, DOCTOR, DOCTOR_RECEPTIONIST, ADMIN.
  • DoctorProfile: Holds credentials and verification flags (PENDING, APPROVED, REJECTED).
  • Slot: Core availability lines. Fields: doctor, date, start_time, status (Available, Locked, Booked).
  • PrescribedLabTest: Linked tests. Tracks checkouts by linking to cart indices.

Custom Permissions & Role Restrictions

Access control permissions protect resources:

  • IsDoctor: Restricts access to approved doctor accounts.
  • IsReceptionist: Restricts access to receptionist accounts assigned to active doctors.
  • IsPatientOwnerOrDoctorReadOnly: Restricts patient vaults. Patients can edit files, but doctors can only read files if shared_with_doctor is toggled.

Django Admin Configurations

Technical overview of custom inline modules, read-only permissions, and bulk operations set up in `/admin/`:

1. Inline Relational Modules

To reduce click-depth, parent models directly display related children lines inside details pages:

  • User Profile Panel: Directly edit PatientProfile or DoctorProfile from User detail layouts.
  • Doctor Profile Inlines: DoctorEducationInline, DoctorExperienceInline, DoctorKeywordInline, and DoctorBoosterInline.
2. Read-Only Ledger Constraints

Database immutability rules prevent accidental deletions of transaction history or verification logs:

# apps/payments/admin.py example
class PaymentAdmin(admin.ModelAdmin):
    def has_add_permission(self, request): return False
    def has_delete_permission(self, request, obj=None): return False

3. Administrative Bulk Actions

Select multiple rows from a model grid to execute bulk operations:

  • Approve/Reject Doctor Licenses: Approving doctor verification files automatically triggers cascades that update the parent profile's status (approved status automatically publishes the doctor to search listings).
  • Refund Transaction Payouts: Bulk process refund transactions and notify payment gateways (Razorpay).
  • Content Moderation: Bulk toggle doctor intro reels and case study boosts.

Axios Client Configuration (`services/api.ts`)

Appends JWT token headers automatically and intercepts 401 Unauthorized responses to refresh the access token silently in the background:

import axios from 'axios';

const api = axios.create({
  baseURL: process.env.NEXT_PUBLIC_API_BASE_URL
});

api.interceptors.request.use((config) => {
  const token = localStorage.getItem('access_token');
  if (token) {
    config.headers.Authorization = `Bearer ${token}`;
  }
  return config;
});

Global State & Styling

PathyaTech handles application state and layouts via lightweight, built-in frameworks:

React Context API State

Global state is managed via `AuthContext` to store logged-in user profiles, JWT tokens, and roles. This prevents prop-drilling across dashboard layouts.

Vanilla CSS Modules

Styling uses global CSS overrides (`globals.css`) alongside route-specific modular files. This isolates view layouts and prevents CSS namespace collision.

Actor Lifecycles & Workflow States

Explore the states, business rules, and technical triggers for each role in the system:

State 1: Account Creation & Onboarding

Trigger: Registers via sign-up page or receptionist portal. Status is set to `PENDING_VERIFICATION`.

Action: Dispatches OTP via Twilio/SMTP. On successful validation, status moves to `ACTIVE` and issues JWT tokens.

State 2: Profile & Vault Setups

Action: Patient configures physical stats and uploads past records. The `shared_with_doctor` flag controls if doctors can view documents.

State 3: Booking & Slot Lock

Action: Patient locks a slot. Unpaid slots are locked for 10 minutes. Successful payment confirms booking and generates a Zoom link.

State 1: Professional Audit

Trigger: Doctor signs up. Account status begins at `PENDING`. Uploads medical licenses to `EntityDocument` for review.

State 2: Clinic Agenda Configurations

Action: Sets operating slots via the availability calendar. This populates database `Slot` rows available for booking.

State 3: Clinical Consultations & AI Interpretation

Action: Reviews patient files, drafts prescriptions, and runs Gemini AI diagnostics or lab report interpreters.

State 1: Account Setup

Trigger: Onboarded by admin and linked to a clinic doctor using a `DoctorAssignment` record.

State 2: Walk-In Reception & Cash Billing

Action: Registers walk-in patients and schedules slots. Confirms appointments directly by logging offline CASH payments.

State 1: Administrative Control

Action: Manages users, verifies doctor profiles/credentials, handles payout accounts, and moderates clinic marketing content.

Detailed Workflow Logic Rules

1. Rescheduling Rules
  • Limits: Maximum of 2 reschedules per appointment.
  • Time Gate: Patients must reschedule at least 3 hours before start time. Doctors can reschedule up to start time.
  • State Gate: Only allowed on CONFIRMED or PENDING_PAYMENT appointments.
2. Verification Cascade logic

Document validations directly control profile states:

  • Approve Cascade: If all credentials in EntityDocument are marked VERIFIED, doctor profile becomes APPROVED and is published.
  • Reject Cascade: If any single document is marked REJECTED, doctor profile becomes REJECTED, blocking their calendar.
